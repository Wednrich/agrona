# Подготовка данных для AGRONA

Этап перед разработкой интерфейса. Загрузчик `scripts/field_data` обращается к источникам, читает значения и сохраняет компактный JSON для передачи Astra. [Казахстан](../data/prepared/kz.json) и [Небраска](../data/prepared/us-ne.json) — пакеты для двух публичных контуров без подтверждённой истории посевов. Основной период — 1 мая–30 сентября 2025 года. Для источников с разовыми снимками и короткими примерами фактические даты указаны в записях.

## Как обновить выборки

Интерфейс запрашивает данные через `/api/field-data`. При запуске Vite или его preview маршрут использует Python из `AGRONA_PYTHON` (по умолчанию `python`) и зависимости `requirements.txt`. В Vercel этот маршрут предоставляет `api/field-data.py`. Он проверяет сессию через Supabase, а для дополнительных источников сверяет переданный контур с сохранённым полем в доступном пользователю хозяйстве. Маршрут `/api/soil` принимает GeoJSON-полигон в исходном формате и использует тот же загрузчик SoilGrids. Для архивов NASA назначьте `EARTHDATA_TOKEN` в окружении сервера. Локальный Vite читает `.env.earthdata`, если файл существует. Для Netlify или другого статического хостинга нужен серверный маршрут с тем же контрактом.

Оценка сохраняется в браузере на 30 дней с ключом по полной границе. Снимок оценки и исходные погодные наблюдения включаются в новые сохранённые сравнения. Оценка вне сравнения пока хранится локально в браузере и повторно загружается на другом устройстве.

Из корня репозитория, в Python-окружении с Node.js 22.6+:

```powershell
python -m pip install -r scripts/field_data/requirements.txt
python -m scripts.field_data --pilot kz --env-file .env --output data/prepared/kz.json
python -m scripts.field_data --pilot us-ne --env-file .env --output data/prepared/us-ne.json
```

Можно указать `--sources soilgrids imerg-power` для повторной проверки только двух источников, `--start` и `--end` для периода, или передать свой GeoJSON-полигон через `--boundary`. Источники, привязанные к Небраске, и календарь с заданной страной проверяются на предусмотренных пилотах. Для NASA Earthdata берётся переменная окружения `EARTHDATA_TOKEN` или только одноимённая запись из указанного файла. Публичные источники работают без неё. Код завершения 1 означает, что как минимум один источник заблокировал запрос. Результаты остальных источников сохраняются.

Для отдельного прогона GES DISC с локальным файлом `.env.earthdata`:

```powershell
python -m scripts.field_data --pilot kz --sources imerg-final gldas --env-file .env.earthdata --output data/prepared/gesdisc-kz.json
python -m scripts.field_data --pilot us-ne --sources imerg-final nldas --env-file .env.earthdata --output data/prepared/gesdisc-us-ne.json
```

Пакет содержит версию формата, контур, запрошенный период и записи `sources`. У записи есть `status`, данные и описание метода или причина пробела. `ready` означает, что удалось извлечь пригодные значения для указанной тестовой задачи. Это не гарантия покрытия на новом поле. `no_coverage` означает отсутствие пригодных данных в проверенном месте, времени или отобранных снимках. `blocked` означает препятствие доступа, транспорта или обработки. `outside_pilot` означает, что выбранный запуск не предназначен для этого регионального источника.

## Реестр исходного списка

Под «выборкой» в таблице понимаются прочитанные значения. Открытый каталог или доступ к файлу не приравниваются к проверенной выборке.

На карточке выбранного поля запускаются запросы NASA POWER и SoilGrids. Во вкладке «Вода» доступны сезонный ряд IMERG через POWER и выборки влажности. Во вкладке «Источники» по тому же контуру загружаются отдельные архивные выборки IMERG Final, SMAP, ECOSTRESS, GLDAS, NLDAS, HLS, Sentinel-2 и высота SRTM. У каждой карточки свой статус, поэтому проблема одного источника оставляет остальные данные доступными. Историческая погода влияет на сравнение планов. Спутниковые выборки показываются как контекст для поля. Они пока не участвуют в расчёте полива. Полноценные ряды HLS и Sentinel-2 и расчёт уклона SRTM остаются отдельными функциями Supabase.

## Передача Astra

Сначала прочитать JSON по обоим контурам и сверить, какие записи пригодны для выбранной задачи. Загрузчики позволяют повторить запросы независимо от интерфейса. Для пользовательского сценария нужно подключить результат загрузки к полю, показать источник и возможность поправки, а также проверить сохранение на новом контуре. При отсутствии проверенного местного календаря сравнение остаётся справочным. Для разработки всей логики с набором, который ещё не подготовлен, сначала закрывается его конкретный пробел из таблицы.

Доступ к GES DISC проверен по фактическому чтению файлов IMERG Final, GLDAS и NLDAS. Одна запись на источник и контур подтверждает загрузку и извлечение значения. Для сезонного сравнения понадобится ряд за нужные даты с проверкой покрытия и пропусков.
